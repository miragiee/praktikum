# Практикум

## Описание проекта

Практикум — это веб-приложение на Laravel для автоматизации организации производственных практик между студентами, университетами и компаниями.

Основная цель проекта — упростить поиск и распределение студентов на практику, оформление заявок компаний, согласование договорённостей между учебным заведением и работодателем, а также ведение документооборота и календаря событий.

Проект подходит для сценариев, где:
- университет публикует и организует практики;
- компании формируют заявки на набор студентов;
- студенты проходят регистрацию, подают данные и участвуют в отборе;
- администратор управляет справочниками и основными сущностями системы.

## Основные возможности

### Для студентов
- регистрация и авторизация;
- просмотр профиля;
- поиск и просмотр информации о компаниях и университетах;
- участие в поиске студентов/подходящих кандидатов;
- работа с заявками и бронями на практики;
- просмотр назначенных мероприятий и резервирований.

### Для компаний
- регистрация и профиль компании;
- создание и управление заявками на практику;
- выбор направления подготовки и необходимого количества студентов;
- оформление договорных запросов с университетом;
- загрузка документов и работа с файлами;
- просмотр календаря и связанных событий.

### Для университетов
- регистрация и управление профилем университета;
- создание и ведение практик;
- работа с контрактами и соглашениями с компаниями;
- управление студентами и направлениями подготовки;
- просмотр календаря активности и договорных запросов.

### Для администратора
- управление справочниками: компании, университеты, студенты, направления;
- управление практиками, документами, договорами и заявками;
- контроль резервирований и контрактных запросов;
- поддержка административного интерфейса системы.

## Роли пользователей

Система использует модель ролей:
- студент;
- компания;
- университет;
- администратор.

Связь между пользователями и сущностями реализована через модели `User`, `Student`, `Company`, `University`, `Role` и связанные классы.

## Ключевые сущности системы

### User
Основная сущность аутентификации. Каждый пользователь привязан к роли и может иметь связанные записи:
- студент;
- компания;
- университет.

### Student
Содержит данные студента: ФИО, курс, направление, университет, электронную почту, качества и навыки.

### Company
Описывает компанию-партнёра: название, ИНН, сайт, описание, контактная информация.

### University
Описывает университет, его контактное лицо, ИНН, описание и данные для взаимодействия.

### Direction
Направление подготовки (например, программирование, дизайн, инженерия и т.п.).

### Internship
Промежуточная сущность практики, связанная с университетом и сроками проведения.

### CompanyRequest
Заявка компании на набор студентов для конкретного направления и практики.

### ContractRequest
Запрос на заключение договора между компанией и университетом.

### Reservation
Бронирование студента на стажировку/практику.

### Document
Документы, загружаемые и связанные с заявками или договорной деятельностью.

## Основные маршруты приложения

В проекте используется маршрутизация в `routes/web.php`. Основные разделы:

- публичные страницы: главная, регистрация, авторизация, поиск студентов;
- пользовательская зона после входа: профили студента, компании и университета;
- операции по заявкам, документам, договорам и резервированиям;
- административный блок с CRUD-операциями для основных сущностей.

Примеры ключевых маршрутов:
- `/` — главная страница;
- `/auth` — форма входа;
- `/register` — регистрация;
- `/profile/student` — профиль студента;
- `/profile/company` — профиль компании;
- `/profile/university` — профиль университета;
- `/admin` — административная панель;
- `/internships` — список практик;
- `/partnerships` — раздел партнёрств;
- `/students-in-search` — публичный поиск студентов.

## Требования для запуска

Перед запуском убедитесь, что установлены:
- PHP 8.3+
- Composer
- Node.js и npm
- база данных SQLite или MySQL
- Git

## Установка и запуск

### 1. Клонирование репозитория

```bash
git clone <repository-url>
cd praktikum
```

### 2. Установка PHP-зависимостей

```bash
composer install
```

### 3. Установка JavaScript-зависимостей

```bash
npm install
```

### 4. Настройка окружения

Скопируйте пример файла окружения:

```bash
copy .env.example .env
```

Если используется SQLite, в `.env` по умолчанию уже задано:

```env
DB_CONNECTION=sqlite
```

Для SQLite можно оставить настройки по умолчанию, если база создаётся автоматически:

```bash
php artisan migrate
```

### 5. Генерация ключа приложения

```bash
php artisan key:generate
```

### 6. Выполнение миграций

```bash
php artisan migrate
```

### 7. Запуск приложения

Для локального запуска:

```bash
php artisan serve
```

Для разработки с фронтендом и Vite:

```bash
npm run dev
```

Либо используется сценарий проекта:

```bash
composer run dev
```

## Типичный сценарий использования

1. Администратор или разработчик создаёт справочники: направления, компании, университеты.
2. Университет создаёт практику и публикует её в системе.
3. Компания формирует заявку на требуемое количество студентов по выбранному направлению.
4. Студент проходит регистрацию и подбирает подходящую практику/компанию.
5. Система фиксирует договорные запросы между компанией и университетом.
6. После согласования назначается практикант, загружаются документы и ведётся учёт событий.
7. Администратор следит за состоянием заявок, бронирований и контрактов.

## Безопасность и конфиденциальность

Проект использует стандартные механизмы Laravel для:
- аутентификации пользователей;
- хеширования паролей;
- работы с сессиями;
- защищённых маршрутов и middleware.

Важно: перед размещением в продакшене рекомендуется:
- настроить реальный `DB_CONNECTION` и безопасные параметры БД;
- настроить почтовый SMTP/доставку уведомлений;
- включить корректную работу с HTTPS;
- проверить права доступа для пользователей и администратора.
